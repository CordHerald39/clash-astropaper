HTTP 401 和「网络连接失败」不在同一层。MDN 说明：响应状态码用来表示某次 HTTP 请求是否已成功完成，并分成 1xx 到 5xx 五类。401 属于 4xx 客户端错误，且语义是未认证，客户端必须先认证才能获得所请求的响应。这要求：TCP/传输已建立，服务器已收到请求并回了状态行。网络连接失败则往往根本没有状态码，请求尚未完成，不能写成 401。

## 适用条件

当你需要判断 Clash 订阅失败到底是凭据问题还是链路问题时使用。已经看到三位数字状态码时，优先按状态码类解释。完全没有状态码时，按连接未完成处理，不要套用 401 的认证含义。

## 区别与判断依据

1. 有没有状态码。401 是服务器给出的完成态回答；域名解析失败、连接被拒绝、握手中断、传输中途断开且未收到状态行，都不属于 401。
2. 状态码类别。2xx 表示成功（200 表示请求成功，具体含义随方法而变）；4xx 表示客户端侧问题；5xx 表示服务器遇到无法妥善处理的情况。401 再具体一点：缺的是认证，不是「网断了」。
3. 和其它「像连不上」的状态分开。408 仍是 HTTP 响应，表示空闲连接上服务器想关掉连接；502 表示作为网关拿到了无效上游响应；504 表示网关等上游超时；503 表示服务未就绪。它们都证明 HTTP 层有回答，只是不是 401。
4. 和邻近认证类状态分开。403 是身份已知但无访问权；407 是代理要求认证；511 是需要认证才能接入网络。只有 401 表示「对这个资源，当前客户端尚未认证」。

## 失败时下一步

日志里只有「失败」「超时」而没有三位码，先做连通性检查，不要改订阅密钥。一旦出现 401，改为核对凭据，不要反复切换接入网络。若码是 5xx，问题在服务器或网关，换凭据通常不会变成 200。若码是 408、502、504、503，按网关或服务就绪处理，并留意是否属于临时状态。无法归类时，把「有无状态码」和「具体数字」分开记录，避免把未完成的请求写成 401。
