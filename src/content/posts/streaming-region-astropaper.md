代理可连接，只表示 Clash 能把已经匹配到该出站的流量送进隧道。平台是否承认账号地区、版权窗口或播放许可，并不是路由规则里的匹配项。官方规则提供的是域名、IP、端口、进程、入站和逻辑组合，没有「账号地区」或「平台权限」字段。把节点连通理解成一定能获得某地区内容，是把出站可达性与站点授权混为一谈。

## 适用条件

节点连通检测通过，但平台仍提示地区、版权或登录环境不符；已经用 `DOMAIN` 或 `GEOSITE` 把站点送进某出口，仍被平台拒绝；需要说明「规则命中了代理为什么仍无权限」。

判断依据：规则行的出站只能是 `DIRECT`、`REJECT` 或代理/组名称，不能填写版权状态。`GEOIP` 匹配的是目标 IP 所属国家代码，不是账号注册地，也不是平台认定的观看地。若提示文案来自内容站点本身，应视为平台侧策略，而不是「规则没连上」。

## 规则能决定的与不能决定的

1. 规则只决定请求被哪条条件选中、送到哪个出站。匹配按从上到下的优先级，`MATCH` 兜底全部剩余请求。这只是流量走向。
2. `DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`DOMAIN-WILDCARD`、`DOMAIN-REGEX`、`GEOSITE` 只描述目标主机名如何匹配。`DOMAIN-SUFFIX` 还有明确边界，例如 `google.com` 不匹配 `content-google.com`。主机名匹配成功并送到某出口，不等于该主机把账号当成该地区用户。`GEOSITE` 匹配列表内域名，部分内容参考 v2fly/domain-list-community，分类名不能理解成已授权地区清单。
3. `IP-CIDR`、`IP-CIDR6`、`IP-SUFFIX`、`IP-ASN`、`GEOIP` 描述目标 IP 的网段、ASN 或国家代码。内容 CDN 的 IP 国家可以和平台品牌国家不同。附加参数 `src` 会把目标 IP 匹配转为来源 IP 匹配，与平台地区更无对应关系。`no-resolve` 只影响是否为匹配去解析 DNS，不赋予任何许可含义。
4. `SRC-GEOIP`、`SRC-IP-CIDR`、`SRC-IP-ASN` 描述客户端地址。同一来源 IP 可以登录不同地区账号，来源条件不能当作账号地区证明。
5. `PROCESS-NAME`、`PROCESS-PATH`、`UID`、`IN-TYPE`、`IN-NAME` 只划分哪类程序、哪类入站走代理。播放器走了代理，平台仍可按账号、支付区或设备历史做判断。
6. `NETWORK` 与 `DST-PORT` 只区分 tcp/udp 和端口。udp 不被节点支持时会继续向下匹配，可能让媒体请求落到直连或另一出口从而播放失败；即便成功命中代理，也不会因此产生平台授权。
7. `AND`、`OR`、`NOT`、`SUB-RULE`、`RULE-SET` 只改变条件组合与引用方式，不会增加「检查订阅是否包含该地区」的能力。

结论应写成：代理可连接是出站可用、且规则把流量送过去的前提之一；平台地区权限是站点用账号和自身策略做的判断。两者在官方规则字段上没有对应关系。

## 出现地区或版权提示时的下一步

先确认请求是否真的命中你以为的那条代理规则，而不是更靠上的 `DIRECT`、`REJECT` 或过宽关键字。未命中代理时，应改顺序或条件，这与权限无关。已经命中目标出口仍出现平台提示时，停止用再加一条 `GEOIP` 去保证权限；`GEOIP` 只能改 IP 走向。下一步应把账号显示地区、目标主机、命中规则出站三项分开记录，出站名称不是许可证。不要把 `GEOSITE` 类别名或 `GEOIP` 国家代码写成套餐地区。同一出口下首页可开、内容域失败时，按域名或后缀分开匹配，仍然只解决走向，不解决授权。
