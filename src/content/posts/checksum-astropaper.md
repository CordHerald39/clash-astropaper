文件哈希解决的是「这一份字节和那一份字节是不是同一串」，不是「这个安装包一定安全、一定官方、一定适合你的电脑」。Clash 电脑端安装包以 GitHub Release 上的具体文件名为准；哈希只有在「摘要来源你已经信任、算法一致、比对的是完整文件」时才有证明力。

## 哈希能证明什么

哈希（常见为 SHA-256 一类摘要）对文件的全部字节做单向计算：输入相同则摘要相同，任一字节被改、被截断或被换成另一份内容，摘要都会对不上。因此，在适用条件下，它只能证明下面几件事。

第一，本地文件与某条「已知摘要」指向同一串字节。传输中途损坏、下载不完整、保存时被截成错误页面，都会表现为摘要不一致。第二，你拿到的是「某一个确定文件名」对应的那份内容，而不是同版本里另一个架构或另一种包装。Release 上 Windows 的 `Clash.Verge_*_x64-setup.exe`、ARM64 安装包、内置 Webview2 的 `*_fixed_webview2-setup.exe`，以及 macOS 的 `*_aarch64.dmg` / `*_x64.dmg`、Linux 的 deb/rpm，都是不同文件，哈希只能说明「这一份没在传输中被改写」，前提是你拿来比对的那条摘要确实对应这个文件名。第三，它可以排除「下到一半、缓存成别的对象、复制损坏」这类完整性问题，不能替代对发布渠道本身的判断。

仓库说明安装包应到发布页下载，并按系统与架构选择：Windows（x64/x86）、Linux（x64/arm64）、macOS 11+（Intel / Apple）。正式版（Stable）面向日常使用；滚动更新的 AutoBuild 可能含缺陷。哈希比对必须钉死到「你选中的那一个资源」，而不是「看起来都叫 Clash 的某个版本」。

## 哈希不能证明什么

哈希不含发布者身份。任何人都能给任意文件算出摘要并贴出来；摘要对得上，只说明你手里的文件和那条摘要来自同一串字节，不说明字节来自项目维护者。若摘要来自镜像、网盘或仿冒页面，比对通过也不能当作官方构建。

它也不能证明 GitHub 账号、Release 页或下载链路未被掉包。你比对的参考值若本身被替换，结果只是「和假参考一致」。它更不能证明软件无恶意逻辑、配置不会被滥用、或适合当前系统：Windows 发布说明写明不再支持 Win7；选错 x64 / ARM64、选错普通安装包与 `fixed_webview2`、把 Linux 的 amd64 deb 用到 ARM，哈希即使「对」也只对错文件负责。

部分 Release 资源旁会带同名 `.sig`。那是签名文件，用途是配合公钥验证「是否由持有对应密钥的一方签发」，与哈希不是同一层证明。有 `.sig` 不等于页面已公布哈希；没有哈希时，不能把「文件名对得上」或「体积差不多」当成完整性证据。

## 适用条件、核对步骤与失败后的处理

适用条件有三条同时成立才有意义：摘要来自你事先信任的渠道（以项目发布页上的对应资源为准，而不是聊天群里的一串字符）；本地计算使用同一算法、覆盖完整文件，而不是只对解压后的某一层或改名副本「目测」；文件名、版本、架构、包装格式与发布说明一致，包括 Windows 是否需要内置 Webview2 变体、macOS 芯片、Linux 的 deb/rpm 与 amd64/arm64/armhf。

可操作步骤如下。只从官方 Release 下载与本机对应的安装包，记下完整文件名（例如某一版的 `Clash.Verge_2.5.7_x64-setup.exe`）。若该渠道对该文件公布了摘要，在本机用系统提供的摘要工具对整个文件计算，再逐字符比对，不要只看前几位。若发布正文以文件名和链接为主、并未给出该文件的哈希，则此时「哈希验证」既不能判通过也不能判失败，完整性与来源需要改看你是否从该发布页取得正确资源，以及（若存在）如何使用随包提供的 `.sig`，而不是用哈希凑结论。选包时以发布说明为准：Windows 区分常用 64 位与不常用 ARM64，以及仅在企业版或无法安装 Webview2 时使用的内置 Webview2 包；macOS 分 Apple M 与 Intel；Linux 按发行版选用 deb 或 rpm。

核对失败时按原因处理，不要忽略不匹配继续安装。摘要不一致：删除本地文件，回到同一官方 Release 重新下载，确认没有下成 HTML 错误页或被中间缓存替换的对象。找不到官方哈希：不要改用论坛或网盘上的字符串；回到仓库指向的 Release 页，以页面实际公布的信息为准。文件名或架构对不上：说明下错变体，应更换正确资源，而不是用哈希「证明可以装」。反复失败：对照仓库的安装说明与文档入口，核对系统是否在支持范围内（例如 Win7 已不在支持之列），并确认比较的是同一个 tag 下的同一个资源，而不是把 Stable 与 AutoBuild、或把 `.exe` 与 `.dmg` 混在一起比。

哈希只回答「字节是否同一串」。身份、构建是否被替换、是否选对安装包，必须靠发布页本身、正确的文件名，以及（若项目提供）签名文件，而不能把摘要当成万能通行证。
