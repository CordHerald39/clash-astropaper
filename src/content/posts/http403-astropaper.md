更新订阅得到 HTTP 403，并不能直接翻译成“订阅过期”。MDN 对 403 的定义是：客户端没有内容访问权，服务器拒绝给出所请求的资源；与 401 不同，服务器已经知道客户端的身份。这段定义没有把 403 绑定到有效期结束。过期、未登录、删除、限速在协议里对应不同或不那么对应的状态码，需要分开看。

## 适用条件

只回答 403 是否一定表示订阅过期。依据是 RFC 9110 与 MDN 释义。若收到未列入的三位码，属于可能定制的非标准响应，更不能解释成过期。本文不讨论计费条款，也不编造客户端到期文案。

判断“一定”的标准是：规范是否把 403 规定为资源超过有效期。结论是否定的。403 只保证这次请求在身份已知之后被拒绝给予内容。

## 403 能证明什么、不能证明什么

能证明：本次以客户端错误类中的 Forbidden 结束；拒绝发生在服务器已知道身份之后。不能证明：该身份的截止时刻、是否过了某日、是否应当续期。这些时间含义并未出现在 403 的说明中。

需要并排排除的码包括：

- 401：语义是未认证，客户端必须先认证自己才能得到所请求响应。缺凭证或凭证不被接受时更接近 401，不是 403，也不是标准的“过期”写法。
- 402：最初与数字支付系统相关，但很少使用，且不存在标准约定。不能把 403 当作 402 的代用，也不能把 402 自动读成到期。
- 404：找不到资源；在 API 中也可表示端点有效但资源本身不存在。服务器还可能用 404 代替 403，以隐藏资源是否存在。因此“看不到内容”不等于过期。
- 410：内容已永久删除且无转发地址，客户端应清除缓存和链接。规范意图包括有时限的促销类服务，但 API 不必用它表示已删除资源。即便见到 410，也是永久删除、无转发，仍不是 403。
- 429：给定时间内请求过多，属于限速。
- 451：因法律原因无法提供。
- 408：空闲连接上服务器希望关掉未使用连接，与是否到期无关。

成功类中，GET 的 200 只说明资源已在消息体中传输；203 还表示元数据与源服务器不完全相同。它们都不能给 403 补上“过期”含义。

## 常见的张冠李戴

把 403 说成过期，是把“现在不能用”这一结果，映射到了规范并未规定的原因。403 与 401 的分界是身份是否已知，不是日历是否过线。403 与 410 的分界是拒绝访问还是永久删除且无转发地址。403 与 404 的分界是禁止还是找不到（含故意隐藏）。若更新过程先出现 3xx 再 403，301、308 只说明 URI 永久改变，302、307 只说明临时改变且今后仍用原 URI，迁址语义同样不包含过期。

## 若仍要把原因查下去

不要在 403 上标注“已过期”作为结论。应保存真实状态码，并向能调整访问权的一方核对该身份为何被拒绝。实际是 401 则先认证；是 410 则按规范清除缓存和链接；是 404 则按不存在或隐藏策略处理；是 429 则按限速理解，而不是按续期理解。503 表示服务器未就绪，可能带 Retry-After，属于暂时不可用，更不是过期。未列出的状态码保持非标准，不能当作过期证据。
