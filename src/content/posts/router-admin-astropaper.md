路由器管理地址在浏览器里也常常以网址形式出现，但在 Clash（mihomo）的 Tun 路由模型里，它是需要按局域网网段识别的目的地址，不是互联网网站。官方文档在 `route-exclude-address` 示例中直接列出 `192.168.0.0/16` 和 `fc00::/7`，把这些前缀从自动全局路由里拿掉，依据就是它们属于本地侧网段，而不是默认要进隧道的公网目的。

## 自动路由处理的是全局流量

`auto-route` 的定义是：自动设置全局路由，可以自动将全局流量路由进入 Tun 网卡。面向互联网的访问，依赖默认路由指向虚接口，再由核心转发。网关管理地址的目的主机是同一广播域或直连三层网络里的设备，通信在到达网关后即结束，并不经过“再去往公网下一跳”。

因此，把管理页当成互联网网站，等于把“目的 IP 属于需要代理的默认路由覆盖范围”套到私网地址上。文档用 `route-address` 的 `0.0.0.0/1` 与 `128.0.0.0/1`（以及 IPv6 的 `::/1`、`8000::/1`）表达接近全表的自定义路由，同时又用 `route-exclude-address` 列出 `192.168.0.0/16`，正是在“尽量全局进 Tun”的前提下，声明哪些目的地不应按互联网路径处理。判断依据：目的地址落在作为排除示例的私网前缀内，就应按局域网例外理解；只有未被排除的公网前缀，才按互联网站点的全局路由理解。`route-address` 一般无需配置，缺省全局路由并不改变私网地址的类别。

## 私网前缀、地址族和解析路径

IPv4 中 `192.168.0.0/16` 是常见的网关网段。管理页使用 `192.168.0.1` 或 `192.168.1.1` 时，这些地址在分配上就是私网，不能当作全球唯一的网站地址。文档把该前缀写在排除列表，而不是当作需要按域名处理的站点，说明配置层认的是网段。IPv6 示例 `fc00::/7` 对应唯一本地地址，同样不是全球可路由的网站。`inet6-address` 只是给虚接口配置 IPv6；系统其他网卡没有 IPv6 时，启动检查可能禁用相关功能。即便浏览器能用 IPv6 字面量打开管理页，该地址仍然是本地侧。

`dns-hijack` 把匹配连接导入内部 DNS 模块，用于处理进入 Tun 的解析。文档明确：MacOS / Windows 无法自动劫持发往局域网的 DNS 请求。这从反面说明，发往局域网的解析与发往互联网的解析被分成两类。路由器管理若依赖局域网 DNS，本来就不是互联网解析路径。Android 开启私人 DNS 时无法自动劫持，同样不能把管理主机名当成已进入面向公网的解析流程。

旧写法 `inet4-route-exclude-address` 与 `inet6-route-exclude-address` 即将废弃，但语义仍是“启用 `auto-route` 时排除自定义网段”，对象依旧是前缀，不是网站主机名。Linux 的 `route-exclude-address-set` 对规则集中的目标 CIDR 匹配则绕过路由，匹配键同样是 IP 前缀。

## 被误当成网站之后怎样回到判断

若把网关名称写成类似公网站点并指望用代理规则去匹配，失败时不要增加与 Tun 入站无关的站点规则来“覆盖路由器”。下一步仍回到地址属性：写出管理页的目的 IP，看它是否属于 `route-exclude-address` 或对应的旧字段。未启用 `auto-route` 时，排除列表不会按自动路由的例外生效，但地址仍是私网，不能改称为互联网网站。

`strict-route` 开启时，Linux 会将连接路由到 Tun，并让不支持的网络无法到达，用于防止地址泄漏。局域网管理地址漏在排除之外，严格路由会按“应进 Tun 的全局流量”处理本地网关，现象会像站点不可达，根因仍是地址类型判断错误。Windows 上严格路由用于处理普通多宿主 DNS 解析造成的泄露，也不意味着管理页变成了互联网站点。Linux 上该规则集绕过若与 `routing-mark` 冲突，或缺少 nftables、`auto-redirect`，绕过不生效，处理步骤是补齐私网 CIDR 排除并确认 `auto-route` 已启用，而不是为管理地址配置面向公网站点的出口。
