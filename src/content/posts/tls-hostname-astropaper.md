证书域名校验确认的是：当前 TLS 对端是否有权为你正在请求的那个主机名说话。随意跳过之后，HTTP 仍可能返回看起来“成功”的状态码，但那些码描述的是“对端认为请求已处理”，并不能证明对端就是你以为的源站。规范里对欺骗性路由、错向请求以及已废弃的代理指示，恰恰说明身份与路由一旦被客户端主动放宽，后续状态码会失去“来自正确源站”这一前提。

## 适用条件：状态码默认假定权威名是对的

HTTP 状态码只在响应已经从某个对端返回之后才有意义。200 OK 表示请求成功，GET 会把资源放进消息体，HEAD 则只有表示头。304 Not Modified 允许继续使用缓存副本。这些成功类码都不验证证书名字；它们只描述已经发生的那一次 HTTP 交换。因此，“跳过域名校验后得到 200”不能作为可以关闭校验的依据。判断是否该保持校验，应看请求 URI 中的 scheme 与 authority 是否仍指向你意图访问的源，而不是看有没有 2xx。

400 Bad Request 把欺骗性请求路由与畸形语法、无效分帧并列，视为客户端错误。关闭主机名校验，等于允许把请求送到另一个名字的对端，却仍在头里声称原来的 Host。这种组合正属于路由被玩弄的情形。421 Misdirected Request 更直接：请求打到了不能为该 scheme 与 authority 组合产生响应的服务器。校验存在时，错误的名字常常在 TLS 就被拦住；校验关闭后，问题会变成一次“看起来像 HTTP、权威却是错的”交换。下一步若校验已被关闭，应重新打开并对齐主机名，而不是用 200 或 404 来回测。

## 为什么成功码和错误码都不能替代校验

203 Non-Authoritative Information 表示元数据并非源站原样，而是来自本地或第三方副本，主要用于镜像或备份；除此之外更宜使用 200。它提醒：HTTP 允许“非权威”信息存在，但那是明确标注的副本语义，不是让客户端自己放弃核对证书名字。305 Use Proxy 在更早的规范中用于指示必须经代理访问，后因带内配置代理的安全顾虑被废弃。这条废弃说明本身就是判断依据：不能依靠响应里的指示去改写信任路径，更不能把“跳过证书域名校验”当成一种便捷代理。

401 Unauthorized 语义是未认证，须先认证才能得到所请求的响应。403 Forbidden 则是身份已知但无权限。两者都假定你正在与预期中的那台源站对话。跳过域名校验后，对端可以伪造 401 以收集凭证，或伪造 200 以投递改写过的配置。404 Not Found 常被用来在未授权客户端面前隐藏资源是否存在，同样以“这是目标源站”为前提。511 Network Authentication Required 表示需要认证才能获得网络访问，描述的是接入网络这一层，不能拿来证明源站身份已经核对。

3xx 中的 Location 会引导客户端改向另一 URI。301 与 308 为永久，302 与 307 为暂时；307 与 308 还要求不得改方法。若域名校验被跳过，跟随 Location 时无法保证下一跳主机仍由合法证书覆盖，重定向链可以在错误的权威上“成功”走完。这不是重定向码的缺陷，而是客户端先放弃了权威名约束。

## 失败且校验已被放宽时的下一步

若已经发生跳过校验后的异常响应，应立即恢复校验，并以“主机名、证书主体、URI authority 一致”为重新测试的前置条件。502 Bad Gateway 与 504 Gateway Timeout 只说明网关没有得到可用上游结果；在校验关闭时，它们不能区分是真的上游故障，还是中间人提供了无法完成的上游。500 是通用服务器错误，503 是暂时不可用（维护或过载），暂时响应若带 Retry-After 应参考其估计时间，且通常不应缓存。这些 5xx 都不构成“可以继续关闭校验”的理由。

425 Too Early 拒绝可能被重放的请求，428 要求条件请求以降低丢失更新，412 表示前置条件不满足。它们保护的是同一权威上的请求完整性，一旦权威名可以任意替换，条件头与重放保护都会套在错误的对端上。下一步只能是恢复域名校验，再对真正的源站解释这些码。

结论性的判断依据是：证书域名校验保证 HTTP 状态码所谈论的“源站”“网关”“代理”仍指向正确名字；缺少这一步，2xx 不再等于取到了预期资源，4xx 不再等于预期源站在拒绝你，5xx 也不再等于预期基础设施出错。因此不能把跳过校验当作排障开关。
