两种网络表现不同，直观上会怪节点，但官方全局配置里大量选项在节点列表之外独立起作用。出站接口、绑定地址、IPv6、运行模式、TCP 并发、统一延迟、进程匹配、Keep Alive 和策略储存，都会让同一批节点走出不同结果。把差异全部归因于节点，会漏掉这些开关。

## 适用条件与不能归因于节点的典型场景

当代理集合未改，只是接入网络变了，就出现成败、快慢或能否被其他设备使用的差别时，应先检查全局项。mode 为 direct 时全局直连，节点不会被用到；为 global 时取决于 GLOBAL 策略组选择；为 rule 时走规则匹配。三种模式与节点是否在线无关，却能单独改变能否出网。profile.store-selected 为 true 时，API 对策略组的选择会被储存供下次启动使用，换网络后仍可能沿用旧选择，看起来像节点不行，实际是储存的选择未变。store-fake-ip 则让域名再次连接时使用原有映射地址，映射生成时所在的网络与当前网络不同时，也会表现为地点差异。

## 全局字段如何独立于节点改变结果

interface-name 指定出站网卡。家庭与办公网卡名不同，或一种网络需要指定接口、另一种不需要，失败点在接口而不是服务器。bind-address 与 allow-lan 决定其他设备能否经代理端口访问；绑定旧 IP，或 lan-disallowed-ips 把当前网段列入黑名单（黑名单优先于白名单），表现为某一地点不能用，此时判断发生在局域网许可阶段。

ipv6 控制内核是否接受 IPv6 流量，默认 true。只有一种网络提供 IPv6 时，双栈行为不同。tcp-concurrent 对解析得到的所有 IP 并发连接并取第一个成功者，DNS 在不同网络返回的地址集合不同，成败可以在并发开关上分叉。unified-delay 开启时会计算 RTT，以消除连接握手等带来的不同类型节点的延迟差异，因此跨网络比较延迟时若该项不一致，数字不能直接当作节点优劣。

find-process-mode 在 always、strict、off 之间切换，改变的是进程是否被匹配，不是节点是否在线。keep-alive-interval、keep-alive-idle 与 disable-keep-alive 改变连接保活；官方将其与移动设备耗电联系起来，不同网络对空闲连接的回收策略不同，中断也可能来自保活。log-level 若为 silent 或 error，会看不到警告级信息，容易把本机配置问题说成节点故障。

## 判断依据与归因失败后的下一步

判断应满足：在 mode、interface-name、ipv6、tcp-concurrent、unified-delay 和策略储存项保持一致后，两种网络仍稳定指向同一代理选择，且日志出现与出站对端相关的错误，才适合讨论节点或链路。若改接口名或绑定地址后现象跟随网络消失，则不应归因于节点。下一步把 log-level 设为 info 或 debug，保存控制台或控制页面输出，对照是否出现接口、绑定或 IPv6 相关记录。Linux 同时核对 routing-mark。GEO 数据模式与加载器影响规则所用数据，内存受限设备默认 memconservative，与节点列表无关。不要用未在本题来源中给出的下载地址代替字段对照。
