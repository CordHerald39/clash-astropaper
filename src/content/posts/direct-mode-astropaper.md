手册把 `direct` 定义为运行模式里的全局直连，与 `rule`、`global` 并列，默认仍是规则模式。因此“直连策略”在这里指内核继续运行、出站固定为直连，而不是进程退出。关闭客户端则是停止该内核，新连接不再经过 Clash 的入站端口和出站逻辑。二者回答的问题不同：前者是“接管仍在、但不再按规则或 GLOBAL 选代理”时的结果；后者是“完全不经过该内核”时操作系统协议栈的结果。

## 适用条件

当你要在“先改 `mode: direct`”和“先退出客户端”之间做对照时，必须先选定要回答的问题。验证规则或 GLOBAL 策略组是否把流量送错，应保留内核、只改运行模式。验证本机是否被内核错误接管，或验证完全不经过代理端口时链路是否正常，应停止内核。把两种操作叠在同一次未记录的实验里，将无法解释到底是模式、出站接口还是进程退出起了作用。`global` 需要在 GLOBAL 策略组选择代理或策略，既不等于 `direct`，也不等于关闭客户端。

## 关闭后消失、直连下仍生效的部分

全局直连时，下列全局配置仍然约束连接：`ipv6` 是否允许内核接受 IPv6 流量；`interface-name` 指定的出站接口；Linux 上的 `routing-mark`；`find-process-mode` 的进程匹配；`allow-lan`、`bind-address`、`lan-allowed-ips`、`lan-disallowed-ips`；`authentication` 与 `skip-auth-prefixes`；`keep-alive-interval`、`keep-alive-idle`、`disable-keep-alive`；`tcp-concurrent`；以及 `log-level` 在控制台和控制页面的输出。外部控制器、可选的 Unix socket / namedpipe / TLS API、外部用户界面路径在内核运行期间也仍然可用。关闭客户端后，这些项不再作用于新连接：不再有代理端口上的用户验证，也不再有局域网二次放行，系统也不会再写出该内核的运行日志。

`profile.store-selected` 用于储存 API 对策略组的选择，供下次启动使用。它只在内核再次启动且该项为 true 时有意义。退出期间不存在“当前直连模式”，下次启动仍按配置中的 `mode` 以及被储存的策略组选择恢复。把退出客户端理解成“清掉所有策略记忆”并不被该字段支持。

## 判断依据与失败时下一步

判断应依据配置语义。若 `mode` 为 `direct`，同时外部控制器仍在监听、日志仍有一般运行内容，说明内核以全局直连工作，不是已关闭。若进程已退出，则当前不存在运行模式。对照失败时：直连失败而关闭客户端后系统访问正常，应优先查仍生效的出站接口、路由标记、IPv6、入站绑定与认证；关闭客户端后同样失败，问题更可能在系统网络或目标侧。下一步不要用观感代替字段核对，先固定一种状态，再在内核仍运行时用 `info` 或 `debug` 日志收集材料。需要排除局域网误接入时，核对 `allow-lan` 与黑名单优先规则，而不是反复开关进程。
