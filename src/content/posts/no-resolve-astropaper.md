在 Clash（mihomo）里，规则匹配过程中触发 DNS 查询，指的是：带着域名的请求已经走到了关于目标 IP 的规则，内核为了判断“该域名的目标 IP 是否落在这条规则里”而去解析。官方原文是：域名开始匹配关于目标 IP 的规则时，mihomo 将触发 DNS 解析来检查域名的目标 IP 是否匹配规则。它服务的是路由匹配，不是另写一套独立的域名规则。

## 适用条件

这一含义只在请求以域名形式进入 `rules`、并且匹配指针来到目标 IP 类规则时成立。目标 IP 类包括 `IP-CIDR`、`IP-CIDR6`（别名，效果相同）、`IP-SUFFIX`、`IP-ASN`、`GEOIP`。`DOMAIN`、`DOMAIN-SUFFIX`、`GEOSITE` 等直接对域名取值，不需要先得到目标 IP 才能判断是否命中。`SRC-IP-CIDR`、`SRC-GEOIP` 等用来源 IP，来源地址随连接存在，也不属于这段“为检查目标 IP 而解析”的表述。`MATCH` 匹配所有请求、无需条件，落到它时已经不需要为核对 IP 范围再解析。

## 触发意味着匹配器缺目标 IP

触发的判断依据是“开始匹配关于目标 IP 的规则”，目的是检查目标 IP 是否匹配该条的 CIDR、后缀、ASN 或国家代码。因此一次触发至少说明三件事：

1. 上方规则尚未结束匹配，请求仍在向下走。优先级是从上到下，顶部高于底部。
2. 当前规则的载荷是 IP 侧条件，域名本身不能直接与 `127.0.0.0/8` 或国家代码比较，必须先有目标 IP。
3. 这次查询是匹配过程的一部分：解析结果用于本条（以及后续仍要看目标 IP 的规则）的比对，而不是改写规则类型。

可以选择 `no-resolve` 跳过这次 DNS 解析，从而让本条在“尚无目标 IP”时不要为了检查而去查询。附加参数 `src` 只把目标 IP 匹配转为来源 IP 匹配，并不描述触发 DNS 的条件，不能用来解释“为什么会查 DNS”。

## 触发之后对后续规则意味着什么

文档补充：如在更早的匹配中触发了 DNS 解析，则依旧会匹配到添加了 `no-resolve` 选项的目标 IP 类规则。含义是：解析一旦在前面发生，目标 IP 已成为匹配上下文里的已知量；后面即使写了跳过解析，也只是不再发起新的查询，并不作废已有 IP，GEOIP 等规则仍可命中。反之，若直到某条带 `no-resolve` 的目标 IP 规则都从未触发过解析，该条就缺少可比较的目标 IP，匹配会继续向下，直到其他类型规则或 `MATCH`。

逻辑规则 `AND`/`OR`/`NOT` 的 payload 里如果出现目标 IP 类型，同样可能在组合条件求值时需要目标 IP；阅读时要注意括号。`RULE-SET`、`SUB-RULE` 只是把匹配转到集合或子规则，并不取消“域名遇上目标 IP 规则就会为检查而解析”这一关系。

## 理解偏差时下一步

若把“规则匹配触发 DNS”理解成任意规则都会查询，下一步应回到类型列表，只保留目标 IP 类作为触发点。若以为加上 `no-resolve` 后整条链路都不会再有目标 IP，应对照“更早触发则依旧匹配”的原文，检查上方是否已有未跳过解析的目标 IP 规则。若无法判断请求当时是域名还是已经是 IP，先按文档把触发条件限定为“域名开始匹配关于目标 IP 的规则”，再沿列表找第一条此类规则，确定查询（或跳过）发生在哪一行。
