基础联网指内核能够按指定接口和地址族把数据包送出主机；代理连接指运行模式不是全局直连时，把流量送入代理端口、策略组或具体出站。二者有固定先后关系：没有可用的出站接口与地址族，后面的规则匹配和节点握手无法成立。全局配置把这两段写在同一层，但生效顺序并不相同。

## 适用条件与模式在顺序中的位置

讨论先后关系的前提是配置已被内核加载，并且能区分运行模式的三个取值。规则匹配按规则分流；全局代理需要在 GLOBAL 策略组选择代理或策略；全局直连不再把流量送入代理选择。此项有默认值，默认为规则模式。模式决定“基础出站之后是否还要再进代理”，它本身不创建网卡，也不代替出站接口。

允许局域网、绑定地址、用户验证发生在入站侧：其他设备先连到代理端口，再由内核按模式处理。因此他机流量的顺序是入站绑定成功，再是模式，再是出站接口。本机流量若不经过这些入站端口，则跳过入站验证，直接进入模式与出站。把本机和他机写成同一条顺序，会得到错误结论。外部控制器用于以接口控制内核，文档中的监听示例为 127.0.0.1:9090，可另配 Unix socket、Windows namedpipe 或 TLS 端口；控制面不插入数据面顺序。从 Unix socket 或 namedpipe 访问接口不会验证密钥，这只影响管理通道安全，不改变数据包先后。

## 从接受到出站的顺序

先决定内核接受什么。IPv6 开关控制是否允许内核接受 IPv6 流量，默认允许。关闭后，IPv6 目标不会进入后续代理逻辑。进程匹配模式控制是否匹配进程：始终开启会强制匹配所有进程；默认由内核判断；关闭则不匹配，路由器上推荐关闭。进程匹配发生在分流识别阶段，晚于数据包被接受，早于最终出站选择。

再做出站。出站接口指定 mihomo 的流量出站接口，文档示例为 en0。无论直连还是经代理，离开本机时都受该接口约束。Linux 下的出站路由标记为出站连接提供默认流量标记，文档示例为 6666，发生在连接真正送出时，晚于模式判定。TCP 并发启用后，会使用 DNS 解析出的所有 IP 进行连接，并采用第一个成功的连接；它改变的是同一出站意图下的建连方式，不能跳过“接口是否正确”这一层。统一延迟开启时会计算 RTT，以消除连接握手等带来的不同类型节点的延迟差异，这只影响延迟对照，发生在代理连接已经能建立之后。

入站侧的允许局域网为真时，其他设备可经代理端口访问互联网。绑定地址决定监听哪些地址。局域网地址段白名单仅在允许局域网为真时生效，默认包含 0.0.0.0/0 与 ::/0，黑名单优先级更高。用户验证作用于 http(s)、socks、mixed，可配置跳过验证的前缀。这些项全部位于代理连接的入口，位于基础出站之前：入站失败时，根本不会进入模式与接口。TCP Keep Alive 的间隔与空闲以秒计，禁用项在 Android 上强制为真，穿插在连接保活阶段，既不是最早的接受条件，也不是代理协议本身。

## 判断依据与失败时如何回退

判断先后关系可用三条依据。其一，模式为全局直连时，链路应在出站接口结束，不再依赖 GLOBAL 策略组；若此时仍失败，问题在基础联网。其二，模式为全局代理或规则匹配时，基础接口必须先能承担直连对照，再解释节点失败。其三，他机访问必须先满足绑定与验证，再谈模式。日志级别决定这些阶段的失败能否被看见：静默不输出；错误级只保留无法使用的失败。控制面的密钥、CORS、DOH 路径和外部用户界面下载，不参与数据面顺序。

失败时按反向顺序回退：先看日志是否把错误打出来；再看模式是否仍是全局代理却被误认为已直连；再看出站接口与 IPv6；最后才看入站绑定与验证。GEO 数据模式、加载器、自动更新间隔属于数据文件，不插在基础联网与代理连接之间。缓存可储存策略组选择和 fakeip 映射，只影响下次启动是否复用选择，不改变本次连接的先后顺序。自定义全局 UA 与 ETag 支持只约束外部资源下载，同样不参与这次先后关系。
