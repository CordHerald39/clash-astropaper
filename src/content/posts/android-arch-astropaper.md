Clash Meta for Android 的安装限制来自两层：一层是 APK 所含原生库的 ABI，一层是应用与系统约定的 Android 版本。二者都会让安装或后续 VPN 能力失败，但失败点和判断方法不同。仓库 Requirement 把它们分开写：最低 Android 5.0，建议 Android 7.0 及以上；架构为 `armeabi-v7a`、`arm64-v8a`、`x86` 或 `x86_64`。Android 平台从 4.0（API 14）提供第三方 `VpnService`，始终开启 VPN 从 7.0（API 24）起由系统在开机后拉起并维持，8.0（API 26）起后台服务受限。平台能力时间线只能解释“装上以后系统能提供什么”，不能与 ABI 混为一谈，也不能把 API 14 误当成该应用的最低版本。

## 架构限制管什么

架构限制管的是进程能否加载 APK 里的原生代码。设备必须在 `armeabi-v7a`、`arm64-v8a`、`x86`、`x86_64` 中与安装包有交集。常见手机是 ARM 系列；`x86`/`x86_64` 多见于部分模拟器或平板。`arm64-v8a` 与 `x86_64` 同为 64 位也不能互换。判断依据：读取 `ro.product.cpu.abi` 或 `abilist`，与 APK 的 ABI 做交集，为空则安装器应拒绝或安装后无法运行原生部分。架构错误通常出现在“包还没变成可启动应用”或“一启动就因库无法加载而退出”，它不经过 VPN 连接请求对话框，也不改变系统关于始终开启 VPN 的开关是否存在。

## 安卓版本限制管什么

版本限制管的是系统 API 与服务生命周期是否存在。低于 5.0，不满足仓库最低要求，应视为不在支持范围。5.0 到 7.0 之间：按最低要求仍可能安装，但系统不会按 7.0 的始终开启模型去开机拉起服务。7.0 及以上才有始终开启 VPN；8.0 及以上若支持这些 API 级别，服务需转入前台，否则后台限制会干扰由系统拉起的连接。首次成为当前 VPN 前，系统会显示连接请求对话框；设置中的 VPN 页（Settings > Network & Internet > VPN）列出已接受请求的应用。版本不足时，缺失的是这些系统能力或服务行为，而不是“CPU 认不认这套指令集”。

## 二者如何区分、失败后怎么走

同一台设备可以版本合格但 ABI 不对，也可以 ABI 匹配但版本低于 5.0。区分方法：若安装阶段即失败且设备 ABI 与包无交集，按架构问题处理，改选四种架构中与设备相交的包。若 ABI 匹配、版本低于 5.0，按版本问题处理，更换设备或系统，而不是换 ABI 包。若已经能安装并出现系统连接请求，说明架构与最低版本至少让应用跑起来了，此后的失败应查 `VpnService.prepare()`、权限是否被撤销、`establish()` 是否因未准备而返回空、是否已有另一个 VPN 占用（每用户或工作资料仅一个活动服务）。需要始终开启却发现系统没有相应选项时，先看是否低于 7.0，或应用是否用元数据退出始终开启；这与 APK 是 `arm64-v8a` 还是 `armeabi-v7a` 无关。按应用分流时“应用未安装”来自目标包名不在设备上，同样不是架构限制。处理顺序应先排除 ABI 与最低版本，再处理 VPN 授权与列表，避免用重签名或乱改包名掩盖真正限制。
