## 前缀长度在规则里代表什么

Clash（mihomo）的 `IP-CIDR` 与 `IP-CIDR6` 匹配 IP 地址范围，payload 采用地址加前缀长度的 CIDR 写法。讨论前缀如何影响匹配范围，适用条件是：该行已经是 CIDR，并且比较的是目标 IP，或经附加参数 `src` 转成的来源 IP，而不是主机名标签。`IP-CIDR` 与 `IP-CIDR6` 效果一样，后者只是别名；同一前缀数字写在 IPv4 与 IPv6 上并不表示同等大小的集合，不能把 IPv4 的 `/32` 习惯直接套到 IPv6 示例上。

规则按从上到下的顺序匹配，列表顶部优先级更高。前缀越长，可变化的主机位越少，范围通常越窄、越具体；前缀越短，范围越大。若把短前缀写在长前缀前面，大范围会先命中，小范围不会再被看到。这是优先级问题，不能解释成前缀本身失去作用。`MATCH` 匹配所有请求且无需条件，前缀再精确的 CIDR 也不能写在它后面。

## 用官方示例看范围如何随前缀伸缩

官方 IPv4 示例为 `IP-CIDR,127.0.0.0/8,DIRECT,no-resolve`。`/8` 表示从左侧起 8 位作为网络前缀，其余位允许在范围内变化，因此该行覆盖以 `127` 为第一段的整块地址，而不是某一个单主机。把前缀改到 IPv4 能表示单地址的长度后，集合会收缩为那一个地址；把前缀改得比 `/8` 更短，集合会比这一整块更大。判断依据：前缀长度增加，能命中的地址集合变小；前缀长度减少，集合变大。

官方 IPv6 示例为 `IP-CIDR6,2620:0:2d0:200::7/32,auto`。这里的 `/32` 是 IPv6 前缀长度，匹配的仍是地址范围，不是只匹配文本里写出的那一个完整地址。IPv6 要表达单主机，通常需要比 `/32` 长得多的前缀。整理规则时必须连同地址族一起读前缀，否则会把大块 IPv6 范围误当成单点。

`IP-SUFFIX` 的示例是 `IP-SUFFIX,8.8.8.8/24,PROXY`，官方定义是匹配 IP 后缀范围。斜线后的数字在这里描述后缀范围，不能按 `IP-CIDR` 那种从左对齐的网络前缀去理解成同一块网段。`SRC-IP-CIDR,192.168.1.201/32,DIRECT` 展示了来源侧把前缀收到单地址的写法。`GEOIP`、`IP-ASN` 不使用 CIDR 前缀，范围由国家代码或 ASN 决定，不能靠加长前缀去缩小它们。`no-resolve` 只决定匹配目标 IP 规则时是否为域名触发解析，不改变 CIDR 集合本身。

## 怎样按范围选用前缀以及失败时下一步

当只要一台目标主机时，把前缀加到该地址族下能够表示单地址的长度。当同一用途落在连续块内时，缩短前缀以覆盖该块，但不要短到把无关地址包进来。多条网段并存时，更长前缀写在更短前缀之上，再下面才是 `GEOIP` 或 `MATCH`。需要把目标匹配改到来源匹配时才使用 `src`，前缀长度的含义不变，变的是拿哪一侧地址来比较。

若实际命中范围与预期不符，下一步先核对前缀是否写在正确的地址族上：例如把 IPv6 的 `/32` 误当成单主机，或把 IPv4 `/8` 误当成单主机。再看列表顺序，短前缀是否抢在长前缀之前。然后区分 `IP-CIDR` 与 `IP-SUFFIX`，避免用同一套从左对齐的口算去核对后缀规则。来源与目标写反时，前缀再具体也比较的是另一侧地址。仍无法解释时，只改前缀长度、不动策略名，将同一目标 IP 放在加长一档与缩短一档的 payload 下对照是否仍命中，从而区分是范围问题还是顺序问题；对照结束后按窄到宽排回列表。
