Clash Verge Rev 电脑端在官方仓库和发布页会同时出现安装包与源码相关文件。二者不能互换：安装包是已经编译并按操作系统打包的客户端；源码压缩包是该版本对应的工程快照，必须自行准备开发环境后才能构建。下面只说明如何区分、如何选择，以及选错或失败后该核对什么。

## 安装包和源码压缩包分别是什么

仓库安装说明写明：请到发布页面下载对应的安装包。发布说明按系统给出的安装包包括 Windows 的 setup 安装程序、macOS 的 dmg、Linux 的 deb 与 rpm。Windows 另提供内置 Webview2 的安装包，并注明体积较大，仅在企业版系统或无法安装 Webview2 时使用；正常版本被标为推荐。Windows 条目同时写明不再支持 Win7。这些文件都是预构建产物，按对应系统完成安装后得到图形界面客户端。

源码压缩包对应的是仓库代码，而不是可执行程序。Development 部分要求：在安装好 Tauri 所需前置条件之后，执行依赖安装、预构建，再启动开发过程。解开源码后看到的是源代码、桌面工程与构建脚本。发布资源中的 `.app.tar.gz` 是已构建应用的归档，`.sig` 用于校验安装包，二者都不是源码，也不能代替安装包。

## 适用条件与判断依据

仅在电脑上使用客户端时，下载与本机系统和 CPU 架构一致的安装包。Windows 常用 64 位正常版本，ARM 设备选择 ARM64 安装程序；企业版或无法安装 Webview2 时，改用发布说明中的内置 Webview2 安装包。macOS 按 Apple M 芯片或 Intel 芯片选择对应 dmg。Linux 的 Debian 系使用 deb，并用 apt 加上本地文件路径安装；Red Hat 系使用 rpm，并用 dnf 加上本地文件路径安装。

需要阅读实现、自行编译、调试或按贡献说明开发时，才使用源码压缩包或仓库源码。判断依据看文件角色：安装包扩展名为 exe、dmg、deb、rpm，文件名含版本号与架构；源码需要完整工具链，不会通过系统安装器变成客户端。仓库对发行通道另有说明：Stable 正式版适合日常使用；AutoBuild 为滚动更新，可能存在缺陷，适合测试反馈。先决定“安装还是编译”，再决定“用哪条发布线”，避免一次下载同时换错类型和通道。

## 操作要点和失败后的下一步

使用安装包时，从 Release 下载匹配文件后按该系统常规方式安装。Linux 保持发布说明中的 apt 或 dnf 本地路径用法。若无法安装或无法启动，先核对三点：系统是否仍为已不再支持的 Win7；架构是否在 x64 与 ARM64 之间下错；企业环境是否缺少 Webview2 因而应改用内置 Webview2 包。服务模式或 TUN 无法使用时，对照当前版本发布说明里针对该系统的修复说明，并到项目文档页查看安装说明与常见问题。不要改下源码压缩包当作可执行程序。

使用源码时，先确认 Tauri 前置条件已就绪，再按 Development 中的命令安装依赖、执行 prebuild 并进入开发运行。说明还写明：普通开发命令会保留开发通道已安装服务的状态；若要显式安装或更新隔离的开发服务，或强制走非特权 Sidecar 流程，应使用仓库给出的对应命令。构建失败应回到 CONTRIBUTING 与 Development 检查环境，而不是改去运行其他系统的安装包或打开 `.sig` 文件。

若仍无法判断下载项：打开同一版本发布说明中的下载地址，按 Windows、macOS、Linux 三节对照文件名；只有在准备自行构建时才处理源码压缩包。类型选对但功能仍异常时，以该版本说明和文档页为准继续排查，而不是在安装包与源码之间反复更换。
