休眠恢复会把机器从断电状态拉回，网卡、地址、路由、IPv6 前缀和 TCP 会话都可能与休眠前不同。全局配置里若干项把这些环境写进了内核行为，因此「配置文件没有改」不等于「网络条件没有变」。下面只说明休眠恢复可能改变哪些网络条件、怎样判断，以及判断失败时下一步。不把未在全局配置中出现的系统菜单写成依据。

## 出站接口与路由条件可能失效

`interface-name` 指定 mihomo 的出站接口，文档示例为 `en0`。休眠恢复后，无线网卡可能关联到不同接入点，有线网卡可能尚未就绪，虚拟接口顺序也可能变化。若该项仍写着休眠前的名称，而系统里该名称暂时不存在，出站条件已经改变：内核会按一个当前无效的接口试图送出流量。未配置该项时，内核依赖系统默认路由；默认路由若在恢复后晚于内核开始转发，同样属于出站条件变化。

Linux 上 `routing-mark` 为出站连接提供默认流量标记。防火墙或策略路由若在恢复后重新加载，同一标记对应的表可能尚未恢复，表现为有标记、无路径。判断依据：恢复后核对本机接口列表是否仍含配置中的名称；在 Linux 上再核对标记是否仍被策略路由识别。接口名还在但无地址、有地址但无默认路由，应分开记录，不要都写成「内核坏了」。

## 地址族、绑定与局域网访问条件可能错位

`ipv6` 控制是否接受 IPv6 流量，可选 true/false，默认为 true。休眠恢复后，IPv6 可能比 IPv4 更晚获得，或因接入网络变化而消失。此时双栈目标的连通条件已经改变，即使 `mode` 仍为 `rule`。判断依据是恢复后系统是否仍有可用的 IPv6 地址，以及失败是否只出现在某一地址族。

`allow-lan` 允许其他设备经过代理端口访问互联网。`bind-address` 为 `*` 绑定所有 IP，也可以绑定单个 IPv4 或单个 IPv6。`lan-allowed-ips` 默认 `0.0.0.0/0` 与 `::/0`；`lan-disallowed-ips` 为黑名单，优先级高于白名单，默认空。休眠前绑定的那一个地址，恢复后可能已经不在本机。判断依据：当前地址是否仍落在绑定与白名单内、是否命中黑名单。`authentication` 为 http(s)/socks/mixed 的用户验证，`skip-auth-prefixes` 设置可跳过验证的 IP 段；文档示例包含 `127.0.0.1/8` 与 `::1/128`。本机地址变化后，谁需要认证、谁可以跳过，都会跟着变。

TCP 层条件同样会变。`keep-alive-interval` 与 `keep-alive-idle` 以秒为单位；`disable-keep-alive` 可关闭 Keep Alive，在 Android 上强制为 true。休眠断开物理链路后，对端或中间设备会丢掉会话。恢复后，旧 TCP 不能再视为同一条连接；Keep Alive 参数没改，只说明内核仍按该间隔发探测，不说明休眠前的套接字还活着。`tcp-concurrent` 为 true 时，会对 DNS 得到的所有 IP 并发，并使用第一个成功的连接；恢复后解析结果或路径质量变化，成功的那一个 IP 可能改变。`unified-delay` 只改变 RTT 计算方式，不改变路径本身。

## 控制面可达性、模式依赖与缓存条件

`mode` 本身是配置值，休眠通常不会改写它，但 `global` 依赖 GLOBAL 策略组的选择，`direct` 则不再走代理。恢复后真正可能改变的是：该模式所依赖的网卡、地址和会话是否还在。把「模式没变」写成「网络条件没变」，会漏掉接口和地址族已经切换的事实。

`external-controller` 监听在指定地址和端口。若绑定的是恢复前才有的地址，控制面可达性就变了。Unix socket、namedpipe、`external-controller-tls` 同理；后两者以及 DOH 路径在文档中写明不会验证 `secret`，恢复后若误用这些通道，访问条件也与带 `secret` 的 HTTP API 不同。Linux 上 `external-controller-routing-mark` 作用于 API 监听 socket，策略路由未恢复时，连控制面都可能受影响。

`profile.store-selected` 与 `store-fake-ip` 决定策略组选择和 fakeip 映射是否保存，供下次启动使用。休眠恢复若并未走完整重启，内存中的映射与磁盘缓存是否一致，属于可能被改变的解析条件，应与开关是否为 true 分开看。`find-process-mode` 为 `always`、`strict`、`off`；进程表在恢复后重建，进程匹配条件也会变。

失败时下一步：先列出恢复后仍有效的接口名与地址族，对照 `interface-name` 和 `ipv6`；再检查 `bind-address` 与 `allow-lan` 是否还指向当前地址；再把 Keep Alive 相关项当作「旧连接不可用」的预期，而不是故障本身。若 API 在恢复后不可达，核对监听地址是否仍存在于本机。`log-level` 用于观察恢复瞬间的 `error` 与 `warning`，不能把 `silent` 下的无输出解释成条件未变。GEO 自动更新、全局客户端指纹、外部用户界面目录与休眠恢复没有直接对应关系，不应列入本次网络条件变化清单。
