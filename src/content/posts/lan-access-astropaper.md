`allow-lan` 被打开之后，改变的不是「本机进程是否走代理」，而是「哪些其他设备可以经过 Clash 的代理端口访问互联网」。官方全局配置把访问范围拆成总开关、绑定地址、允许网段和禁止网段四层，并与代理用户验证叠加。理解这几层各自放大或收缩了什么，才能判断局域网共享到底暴露到哪里。

## 总开关只决定「代理端口是否对其他设备开放」

适用条件：讨论对象是 http(s) / socks / mixed 等代理端口的入站，而不是规则模式、出站接口或外部控制 API。

`allow-lan` 可选 `true` 或 `false`。文档原意：允许其他设备经过 Clash 的代理端口访问互联网。

判断依据：

- 为 `false` 时，访问范围停在「不把这些代理端口提供给其他设备」，即使主机有局域网地址也不构成共享。
- 为 `true` 时，才进入后续范围控制；它本身并不指定「绑在哪块地址」或「哪些 IP 能来」。
- 运行模式 `mode`（`rule` / `global` / `direct`）决定的是流量如何匹配出站，并不替代 `allow-lan` 的入站范围。

失败时下一步：若你观察到其他设备仍不能使用代理端口，先确认当前加载配置里 `allow-lan` 确为 `true`，再解释绑定与网段；不要把「模式是 rule 还是 global」当成访问范围已经改变的依据。

## 绑定地址决定「对端必须打到哪一个本机地址」

适用条件：`allow-lan` 已为 `true`，需要明确其他设备能使用的入口地址集合。

`bind-address` 的文档含义是：仅允许其他设备通过这个地址访问。可选形态包括：

- `"*"`：绑定所有 IP 地址，访问范围在地址层面放到主机拥有的全部地址。
- 单个 IPv4，如 `192.168.31.31`：访问范围收缩为「只能打这一张 IPv4」。
- 单个 IPv6，如 `[aaaa::a8aa:ff:fe09:57d8]`：访问范围收缩为「只能打这一张 IPv6」。

与此同时，`ipv6` 控制内核是否接受 IPv6 流量，可选 `true`/`false`，默认为 `true`。若为 `false`，即使绑定写法看起来包含 IPv6，实际可接受的范围也不包含 IPv6 流量。

判断依据：

- 从「本机回环可访问」变成「局域网其他主机可访问」，前提是绑定地址是对端路由可达的地址，而不是仅 `127.0.0.1` 这类对端到不了的入口。
- 单地址绑定不会自动覆盖主机上的其他网卡地址；多网卡时，访问范围以绑定值为准，而不是「主机有哪些地址」。
- `external-controller` 把 `127.0.0.1` 改成 `0.0.0.0` 改变的是 API 监听范围，文档将其归在外部控制，不属于「经过代理端口访问互联网」的同一范围描述。

失败时下一步：用对端实际填写的代理主机，对照 `bind-address` 是否包含该地址。若只绑了已失效的旧局域网 IP，访问范围在纸面上存在、在路由上为零。需要 IPv6 客户端时，同时核对 `ipv6` 与 IPv6 绑定写法。

## 允许网段、禁止网段和认证决定「哪些源 IP 真正进得来」

适用条件：入口地址已经能被对端打到，还要看源地址过滤和是否要求凭据。

`lan-allowed-ips` 仅作用于 `allow-lan` 为 `true`，表示允许连接的 IP 地址段，默认 `0.0.0.0/0` 和 `::/0`。这意味着在未改名单时，源地址层面默认覆盖全部 IPv4 与 IPv6。

`lan-disallowed-ips` 是禁止连接的 IP 地址段，黑名单优先级高于白名单，默认空。文档示例 `192.168.0.3/32` 说明可以把单个主机从可访问范围里剔除。

因此访问范围的实际集合是：绑定地址可达，且源 IP ∈ 允许段，且源 IP ∉ 禁止段。

`authentication` 为 http(s) / socks / mixed 的用户验证。`skip-auth-prefixes` 设置允许跳过验证的 IP 段，文档示例为 `127.0.0.1/8` 和 `::1/128`。认证不改「谁能打到端口」的地址范围，但会把「未持有凭据的源」挡在可用范围之外；能跳过验证的默认只覆盖本机回环，不覆盖整个局域网。

操作与判断：

1. 未自定义 `lan-allowed-ips` 时，不要把默认值理解成「只允许 192.168.0.0/16」之类更小的局域网；默认是全地址。
2. 一旦写入更小的允许段，同一二层网络里落在段外的设备即不在访问范围内。
3. 黑名单优先，故「允许 0.0.0.0/0」加上「禁止某 /32」后，范围是全集减去该主机。
4. 配置了 `authentication` 后，有效访问范围还要叠加「提供了列表中的用户名密码，或源 IP 命中 `skip-auth-prefixes`」。

失败时下一步：若范围比预期更大，收紧 `bind-address` 或 `lan-allowed-ips`，并检查是否误把 `external-controller` 改成全接口监听。若范围比预期更小，先看黑名单和认证，再看绑定是否只选了单地址。停止共享时，把 `allow-lan` 设回 `false` 才会从总开关上收回「其他设备经过代理端口」这一层访问范围。
