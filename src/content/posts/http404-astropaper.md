Clash 更新订阅得到 HTTP 404，只能说明「这一次被请求的资源，服务器表示找不到」。它不能单独证明账号已经失效。MDN 对 404 的定义是：服务器找不到所请求的资源；浏览器里意味着 URL 不被识别；API 里也可以是端点有效但资源本身不存在。同一页还写明：服务器可能故意返回 404 来代替 403，以便对未授权客户端隐瞒资源是否存在。因此 404 是「找不到」的对外表现，不是「身份已作废」的充分条件。

## 适用条件

适用于：已经看到 404，有人据此推断订阅账号过期、被封或欠费。不适用于：没有状态码的连接失败，或已经明确是 401、403、410 的情形。那些码有各自的语义，不可与 404 混为一谈。

## 404 与账号失效不能划等号的依据

1. 404 首先指向资源定位。路径写错、订阅 ID 不存在、复制截断，都会让 URL 不被识别或让 API 资源不存在，账号本身可能仍有效。判断依据是：只改路径或资源标识后出现 200，GET 已成功取出资源，说明先前不是账号问题。
2. 认证与授权有单独的码。401 的语义是未认证，客户端必须先认证才能拿到所请求响应。403 表示客户端没有访问权，且与 401 不同，服务器已经知道客户端身份。若账号失效或权限被收回，更接近这两类完成态，而不是必须用 404 表达。
3. 404 可能是 403 的掩饰。MDN 明确允许服务器用 404 代替 403 来隐藏资源存在性。此时真实原因可能是「已知你是谁，但不给你看」，对外仍显示找不到。单看 404 无法区分「路径没有这个资源」和「不想承认有这个资源」。
4. 永久删除也不是 404 的专利。410 表示内容已永久删除且无转发地址，客户端宜去掉缓存和链接。若把任意 404 都当成账号作废，会错过 410 这种更适合清理本地记录的信号，也会把 301、308 这种「地址永久更换」误判成失效。
5. 临时限制更不是失效。429 是单位时间内请求过多，503 是服务未就绪，502、504 是网关侧失败。它们都可以让更新失败，但都不等于账号无效。

## 失败时下一步

同时记录状态码、脱敏路径和是否曾出现 401 或 403。只有 404 时，先核对 URL 是否被识别，再考虑提供者是否用 404 隐藏授权失败。在出现 401、403 或提供者明确说明之前，不要把 404 写成账号失效结论。若随后变为 410 或 301、308，按删除或改址处理，仍不要回填成「账号无效」。
