在 Windows 上，Clash Verge Rev 的官方材料把「把客户端装到电脑上」和「让代理真正生效」写成两条线。发布页提供的是安装包；仓库功能列表则把配置文件管理、系统代理、TUN（虚拟网卡）和内置内核，作为安装之后才成立的能力。安装成功只说明本机有了图形界面和内核文件，并不等于流量已经按代理规则转发。

## 适用条件

本说明只针对从官方发布页获取的 Windows 安装包，用来区分「客户端已安装」和「代理已配置」。发布说明写明不再支持 Win7。不适用于把已废弃的 Alpha 或可能存在缺陷的 AutoBuild 直接当成正式安装结果，也不把其他系统上的故障套到 Windows。

判断是否该按「两件事」来看：应用窗口已经能打开，但仍无法确定内核是否在运行、配置是否已成为内核输入、系统代理或 TUN 是否实际接管流量。若窗口本身都打不开，应先回到安装包选择，而不是进入代理层排查。

## 安装客户端实际完成的范围

官方仓库的安装说明是：到发布页下载对应安装包。Windows 还要按官方分类选文件：常用的 64 位正常版本（推荐）、不常用的 ARM64，以及仅在企业版系统或无法安装 Webview2 时使用的内置 Webview2 版。这一步落下的是基于 Tauri 的图形界面，以及内置的 Clash.Meta（mihomo）内核，而不是一份已经生效的代理策略。

同一份发布说明把 Windows 服务写成另一类问题：部分系统安装服务失败并提示 `program not found`；未安装服务时以普通权限运行，内核可能无法启动；旧版服务状态残留会妨碍重装；系统盘删除权限或系统隔离被误判时，服务模式和 TUN 会不可用。可见安装包运行结束，并不自动等于服务已装好，也不等于内核已启动。

可对照的依据只有两条：安装包文件名能在该标签资产列表中找到；应用可以启动。这两条只证明客户端在，不证明代理层就绪。

## 配置代理为何必须另算一步

仓库把「配置文件管理和增强（Merge 和 Script）」「系统代理和守卫」「TUN 模式」与下载安装包分开列出。发布说明还出现过：订阅与 DNS 覆写、内核未运行时界面仍显示服务模式、服务因路径或目录权限无法启动内核、首次以管理员身份启动后因数据目录所有权不符而拒绝启动内核。说明安装之后至少还有三层独立条件。

第一层是内核进程确实在运行。界面显示服务模式，并不能代替内核已启动。第二层是配置或订阅已经作为内核输入存在；Merge、Script、DNS 覆写属于配置层，会随订阅和重启变化，不会因为安装包在磁盘上就自动齐备。第三层是流量入口：系统代理或 TUN 都依赖服务与权限检查通过，失败时表现是服务模式或 TUN 不可用，而不是安装包缺失。

因此：重装客户端解决不了「没有可用配置」；安装包完好也替代不了「内核因服务或权限没起来」；内核起来了也不等于系统代理或 TUN 已经接管。这三句对不上时，应把问题留在对应那一层。

## 失败时下一步

窗口无法启动或安装包类别不对：回到发布页，按 Windows 分类选择正式版标签下的文件；Win7 按官方说明不在支持范围。窗口能开但内核起不来：优先看成服务是否安装、路径与权限、旧服务残留；较新的发布说明会给出原因，而不是只显示「服务无法启动内核」。内核在跑但访问未按预期走代理：检查配置或订阅是否有效，以及系统代理或 TUN 是否因权限检查失败而不可用，避免无依据地反复重装。若当前渠道是 Alpha 或 AutoBuild，按仓库说明改回 Release 正式版后再按上述层次排查。来源对不上官方仓库时，应丢弃该安装结果，仅从官方仓库指引的发布页重新获取。
