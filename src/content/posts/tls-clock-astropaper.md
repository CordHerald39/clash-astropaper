证书有效期与本机时钟的关系，不能从 Clash 界面去编造，而要从“HTTP 请求何时算完成”来理解。官方状态码材料说明：响应状态码指示特定 HTTP 请求是否已成功完成，并分为五类。TLS 在 HTTP 之前用本机当前时间与证书的起止时刻做比较；比较失败则往往根本不会产生这些状态码。因此关系可以表述为：本机时钟是证书有效期判断的参照系；参照系偏移时，你看不到成功或失败的 HTTP 完成码，而不是看到某一个叫“过期”的状态码。清单里不存在专门的证书时间编号。

## 适用条件：何时需要讨论时钟与有效期

适用条件是使用 HTTPS 获取资源（包括配置），并且关心握手能否进入 HTTP。若通信已经返回 200，则 GET 的结果是资源已被取回并出现在消息体中，证书有效期在该次连接上已被接受，本机时钟至少落在对端证书所允许的窗口内。资料并不描述任何绕过校验的机制。若返回 201、202、203、206，同样属于成功类，说明有效期比较未阻止请求完成。202 表示已收到但尚未处理，并且 HTTP 无法稍后异步告知结局；即便如此，它仍是已完成的 HTTP 响应。

相反，若没有任何信息、成功、重定向、客户端或服务器错误码，时钟与有效期的关系才成为需要首先排除的假设。资料提醒未列出的响应可能是自定义非标准码；自定义码仍证明 HTTP 已完成，不能用来说明时钟越界。401 与 407 涉及认证，403 涉及权限，404 涉及资源是否存在，它们都要求握手成功。把这些码解释成证书过期缺少依据。

## 比较顺序与可观察结果

关系分三层。第一层，本机时钟提供“现在”，证书有效期是一段起止时间。若“现在”早于起始或晚于截止，校验失败，HTTP 五类状态都不应作为该次失败的标签。第二层，一旦校验通过，状态码才开始描述请求完成情况：301 表示 URL 永久改变，302 为临时改变且将来仍可能变化，307 与 308 强调不得改变方法。能够执行重定向，意味着有效期与时钟的比较已经结束。第三层，4xx 与 5xx 描述的是请求内容、权限、限流、网关或源站，不是证书起止时刻。412 是条件请求的前提不被满足，428 要求请求必须是条件性的，409 是与服务器当前状态冲突；它们都以 HTTP 语义为前提。

判断依据是：若只看到 TLS 失败而没有 1xx–5xx，优先怀疑本机时钟与有效期窗口的相对位置。500 的含义是服务器遇到不知如何处理的情况，且偏通用，不能当作证书过期的别名。502 是网关得到无效响应，504 是网关不能及时得到响应，503 是暂时不能处理；它们出现时，时钟与有效期关系已经不是当前可观察变量。

## 操作步骤与失败时下一步

不要编造对时界面。可执行步骤是：记录本机当前时间（含时区）与错误是否伴随任何状态码；若无状态码，将时钟校正到可靠时间源后再请求一次同一资源。校正后出现 200 或 304，说明有效期窗口已容纳本机“现在”，304 还说明缓存副本可继续使用。校正后出现 401 或 407，说明窗口已满足，下一步是认证而不是继续调时。校正后出现 451，表示因法律原因不能提供资源。校正后仍无状态码，则关系假设未得到 HTTP 层佐证，下一步应考虑主机名、信任链或协议不匹配等资料未展开的问题，同时避免关闭校验——状态码规范并不把关闭校验列为完成请求的手段。若校正后出现 425，服务器不愿冒险处理可能被重放的请求；出现 426 则应查看 Upgrade。这些都是时钟已经不再阻断握手的信号。向他人说明二者关系时，应使用可观察标准：无状态码时关系可能成立；有 2xx–5xx 时关系在该次请求上不成立。
