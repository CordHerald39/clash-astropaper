在 Linux 上，Clash Verge Rev 的窗口和真正转发流量的进程不是同一个东西。仓库把它定义为基于 Tauri 的 Clash Meta 图形界面，并写明内置 Clash.Meta（mihomo）内核，还可以切换 Alpha 版本内核。分清这两层，才能理解「窗口还在、代理已经不在」或「内核已停、界面仍显示服务模式」。

## 适用条件

本说明只针对已经按发布页装好 DEB 或 RPM、需要分辨系统代理、TUN、服务模式和 Sidecar 各管什么的场景。它不代替选包，也不解释某个订阅字段。开发文档中的 `pnpm dev` 只描述开发通道如何复用或避开已安装服务，日常使用仍以发布页安装包为准。

## 桌面客户端做什么

客户端是 GUI，负责配置展示与编辑、Merge 与 Script 增强、语法提示、主题与托盘外观、可视化节点和规则、WebDav 备份，以及把系统代理、TUN 等开关交给内核落地。它还可以安装或修复系统服务。

判断依据：你在改订阅、覆写、外观或备份时，对象是客户端。开发说明写明，服务未安装时应用以 Sidecar 启动（无特权、内核作为旁路进程）；需要服务时则须安装或更新服务。因此「打开了窗口」只证明 GUI 进程起来了。发布记录还显示，内核未运行时首页仍可能显示服务模式，界面文案不能当成内核状态。

## 代理内核做什么

内核负责按规则做隧道与代理。系统代理把流量指到内核监听端口；TUN 由内核配合虚拟网卡接管。服务模式下，内核由系统服务拉起，生命周期不与 GUI 完全绑定；Sidecar 下则随旁路进程启动。

判断依据：报错含「内核无法启动」「服务模式内核意外停止」「TUN 不可用」时，对象是内核或服务。发布说明曾指出，服务模式停止或重启内核时若直接强制结束，内核来不及正常退出，最后日志会丢失。较新版本把服务自身运行日志保存到文件，用来追查内核被停止的原因。Linux 上还出现过安装或修复服务后仍无法启动内核、无法开启 TUN，说明 GUI 里的 TUN 开关不能单独生效。

## 二者如何配合，以及失败时下一步

1. GUI 读取本地配置（含 Merge、Script、DNS 覆写），形成交给内核的生效配置。
2. 按当前选择，经系统服务或 Sidecar 启动内核。
3. 内核起来后，再处理系统代理或 TUN。配置与日志只保存在本地。

窗口起不来：先查安装包与客户端进程。窗口在但内核不起：查服务是否安装、数据目录所有权、升级后服务版本或协议是否兼容（不兼容会提示重新安装服务）、重装服务后内核文件是否缺失。内核在但流量不对：再查订阅与覆写。不要把 GUI 发布频道（Stable / AutoBuild）和内置内核 Alpha 切换当成同一次更换。
