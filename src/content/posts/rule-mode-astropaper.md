在全局配置里，一条连接的去向首先由运行模式切开：`rule` 表示规则匹配，`global` 表示全局代理（需要在 `GLOBAL` 策略组选择代理或策略），`direct` 表示全局直连。该项默认为规则模式。本页只定义这三种模式，不包含路由规则如何逐条比较。因此「规则模式如何决定去向」在本页的边界是：连接进入规则匹配，而不是进入全局出口或全局直连；匹配过程还可能用到本页给出的进程匹配、IPv6、出站接口和 GEO 数据条件。

## 适用条件

适用于需要从全局配置理解 `mode: rule` 含义、并把它和 `global`、`direct` 区分开的场合。适用于已经处于规则模式、还要判断进程匹配、地址族、出站网卡或 GEO 文件会不会改变匹配条件的场合。不适用于在本页寻找规则列表、策略组节点表或 DNS 细则——那些键未在本页展开。

## 模式与附加条件怎样起作用

1. 先看模式本身。`rule`：按规则匹配决定去向。`global`：不再按规则表分流，出口落在 `GLOBAL` 策略组所选的代理或策略。`direct`：全局直连。判断：同一条连接，只有在 `rule` 下才谈「规则匹配的结果」；切到另外两种模式后，去向由全局策略覆盖。省略 `mode` 时按默认规则模式理解。
2. 再看匹配条件是否被全局项关掉。`find-process-mode` 控制是否让 Clash 去匹配进程：`always` 强制匹配所有进程，`strict` 默认并由内核判断是否开启，`off` 不匹配。资料建议路由器使用 `off`。判断：规则匹配若依赖进程信息，`off` 会使这条路径不具备进程维度，去向只能建立在其余仍可用的条件上。本页未写出进程规则语法，只提供是否匹配进程的开关。
3. 再看出站路径。`ipv6` 为 false 时内核不接受 IPv6 流量，IPv6 连接进不了后续匹配。`interface-name` 指定流量出站接口；Linux 上 `routing-mark` 为出站连接提供默认流量标记。`tcp-concurrent` 为 true 时，使用 dns 解析出的所有 IP 连接并采用第一个成功的连接，实际落到的对端地址可能与只试其中一个 IP 时不同。判断：模式仍是 `rule`，但出站网卡、标记或并发选中的 IP 变了，观察到的「去向」也可以变。
4. GEO 数据是匹配用的资料，不是模式本身。`geodata-mode`、`geodata-loader`、`geo-auto-update`、`geo-update-interval` 与 `geox-url`（geoip、geosite、mmdb、asn）决定加载哪种文件、从哪下载、是否按小时间隔更新。判断：规则模式声明的是「做规则匹配」；若匹配依赖这些数据文件，文件模式或地址错误会影响匹配所依据的数据，但本页没有把 GEO 文件直接写成一条连接的出口。

## 失败时下一步

无法解释某条连接的出口时，先书面写出当前 `mode` 取值，排除 `global` 与 `direct`。仍在 `rule` 下则检查 `find-process-mode`、`ipv6`、`interface-name`、`routing-mark`、`tcp-concurrent` 和 GEO 加载项是否把匹配条件改掉。需要具体哪一条规则命中时，本页没有命中记录字段，应转到实际承载规则表的配置，而不是在全局项里补写规则算法。日志仅出现在控制台和控制页面，可把 `log-level` 调到 `debug` 以获得更多运行信息，资料并未规定日志会打印去向决策树。
