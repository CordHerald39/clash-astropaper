最小复现要控制网络变量和目标变量，是因为全局配置里很多键会改写“谁可以进来、从哪出去、用哪套地址、怎样算成功”。这些值若不冻结，同一份精简配置也会走到不同路径，看起来像随机失败。适用条件是：故障依赖某类目标、某一地址族、某一块网卡，或局域网里的另一台设备；此时先冻结边界，再谈删减。

## 网络变量改变可达边界

`allow-lan` 决定其他设备能否经代理端口访问互联网。`bind-address` 决定绑定全部地址还是单个 IPv4 或 IPv6。`lan-allowed-ips` 默认覆盖所有 IPv4 与 IPv6 网段，`lan-disallowed-ips` 作为黑名单优先于白名单。测试机若有多块地址或处于共享网络，不写下 bind 与允许/禁止网段，复现可能来自另一块地址上的无关客户端。`authentication` 与 `skip-auth-prefixes`（文档示例包含 `127.0.0.1/8` 与 `::1/128`）会把“能连上”变成鉴权结果。控制网络变量，就是把入站边界写成与故障当场一致，避免把鉴权失败或绑定范围失败当成业务故障。

`ipv6` 控制内核是否接受 IPv6 流量。目标同时有两族地址时，失败可能只在其中一族出现。`interface-name` 指定出站接口，`routing-mark` 在 Linux 为出站连接提供默认标记，二者直接决定数据包离开本机的面。默认路由若在实验中途被系统改写，等于换了一张网做测试。

## 目标变量改变成功的定义

`mode` 为 `rule`、`global` 或 `direct` 时，同一目标分别走规则匹配、GLOBAL 策略组或全局直连。模式不固定，就无法说明故障属于匹配、代理还是直连路径。`tcp-concurrent` 会对解析得到的全部 IP 发起连接并采用第一个成功者，目标从“某一个地址”变成“地址集合中的最快成功者”。记录最小场景时应写明当时采用的是并发还是单地址，因为并发开启时一次成功不能代表列表中其他 IP 也可达。`unified-delay` 用 RTT 消除握手造成的类型差异，延迟类故障在开关前后数字不可比。

`find-process-mode` 把进程加入匹配：`always` 强制匹配所有进程，`strict` 由内核判断，`off` 不匹配。同一目标在不同进程下结果可以不同。Keep Alive 间隔、空闲与禁用项改变长连接是否被探测包维持；资料指出修改它们可减少移动设备耗电，在电脑端也会让“过一段时间才断”随这些值漂移。GEO 自动更新、更新间隔、ETag 与自定义 UA 可能在两次运行之间替换 GEO 文件，站点分类随之改变。外部控制器监听 `127.0.0.1` 还是全部地址，以及是否开启不验证 secret 的 Unix socket 或 namedpipe，会把控制面流量混进观察窗口。

## 操作原则与失败下一步

先列出当场常量：模式、IPv6 开关、bind、出站接口、是否 TCP 并发、进程匹配模式、是否自动更新 GEO。复现过程中只允许改正在检验的那一个假设。判断依据是：在既定 `log-level` 下，同一目标仍出现同一类 error、warning 或 info，且入站来源、出站接口没有换成别的地址。

控制后仍不能复现时，不要立刻认定问题已消失。下一步核对是否忽略了默认值：`mode` 默认 rule，`ipv6` 默认 true，LAN 允许网段默认全通，进程匹配默认 strict，ETag 默认 true，GEO 加载器默认 `memconservative`。记录值与默认值不一致的项就是失控变量。双栈目标只测了单族时，补测另一族，但保持其余网络项不变。Linux 上若配置了 `routing-mark`，确认标记没有被系统策略在中途改写。
