Clash 全局配置里的 `bind-address` 描述的是：其他设备只能通过这个地址访问代理入口。官方给出两类写法：`*` 表示绑定所有 IP 地址；也可以写成单个 IPv4，或用方括号写成单个 IPv6。所谓绑定所有接口，对应的是前一种；绑定回环地址，则是把该值写成只能由本机进程到达的回环地址（IPv4 的 `127.0.0.1`、IPv6 的 `::1`）。二者差在「入口挂在哪些本机地址上」，以及「哪些客户端在三层上能够把包送到这个入口」。

## 绑定所有 IP 地址覆盖什么

`bind-address` 为 `*` 时，内核按文档绑定所有 IP 地址。在 `allow-lan` 为 `true` 的前提下，本机当时持有的各接口地址都可能成为代理入口，对端可以选择其中任一路由可达的地址来连接。

适用条件是：需要把代理端口提供给其他设备，并且本机地址集合不固定（多网卡、地址会变），又不打算每次改单地址。判断依据有两条：配置值确实是 `*`；同时 `allow-lan` 为 `true`。只绑定全部地址但未允许局域网，仍不能按「已向其他设备开放」理解。`allow-lan` 的官方含义是允许其他设备经过 Clash 的代理端口访问互联网，它与绑定范围是叠加关系，不是同义词。

## 绑定回环或单个地址时可达性如何变化

写成单个地址时，官方含义变为「仅允许其他设备通过这个地址访问」。回环地址不属于其他设备可路由到达的接口地址：本机进程可以把代理服务器填成 `127.0.0.1` 或 `::1`，其他主机即使与你在同一链路，也无法把目的地址写成你的回环。因此绑定回环的效果是入口只对本机开放。

绑定某一块网卡上的非回环单播地址，介于「全部地址」和「仅回环」之间。对端必须指向该单播地址，并且网络路径必须能到达该地址。文档中的 IPv4 示例形态是具体主机地址，IPv6 则使用方括号包裹。判断依据看绑定值属于哪一类：`*`、回环、还是某张网卡上的非回环地址。三类的可达集合不同，不能互相替代。

外部控制面有平行对比：`external-controller` 文档示例为 `127.0.0.1:9090`，并写明可改成 `0.0.0.0` 以监听所有 IP。这只用来理解「回环监听」与「全地址监听」在套接字上的差别。API 端口不是代理端口，讨论绑定接口时必须分开。

## 与 allow-lan、地址段叠加后的效果

`lan-allowed-ips` 仅在 `allow-lan` 为 `true` 时生效，默认 `0.0.0.0/0` 与 `::/0`。`lan-disallowed-ips` 是禁止连接的地址段，黑名单优先级高于白名单，默认空。于是会出现这些组合：绑定 `*` 但白名单很窄，入口地址虽然出现在多张网卡上，却只有特定源 IP 能用；绑定回环时，再宽的白名单也不能让远端到达回环，因为数据包到不了该目的地址。

`skip-auth-prefixes` 的文档示例包含 `127.0.0.1/8` 与 `::1/128`，说明回环来源常被单独免验证。这是用户验证策略，不是把绑定从回环改成全部接口。`ipv6` 控制内核是否接受 IPv6 流量：即使绑定了 IPv6 地址或 `*`，关闭 IPv6 接受后，IPv6 入口仍不应被当成可用路径。

## 选错之后如何判断和下一步

目标仅本机：绑定回环，或关闭 `allow-lan`。目标是局域网共享：`allow-lan` 为 `true`，并使用 `*` 或当前局域网单播地址。本机通、旁设备不通：先看绑定是否为回环，或是否为对端路由不到的单地址。所有网卡都能被当成入口且超出预期：当前是 `*`，且来源段过宽，应改成单地址，或收紧 `lan-allowed-ips`，必要时用 `lan-disallowed-ips` 排除特定主机。

仍不符合预期时，确认配置已加载，把 `log-level` 调到可以看到错误与警告，并在系统层查看各地址上的实际监听。不要把出站 `interface-name` 误当成入站绑定。
